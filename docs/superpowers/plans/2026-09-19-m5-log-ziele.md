# M5: Spiel-Log im Browser, Spieler als Ziel, Kleinigkeiten – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Forges Spiel-Log läuft live und kategorisiert im Browser mit (inkl. Nachladen beim Reconnect); Spieler sind erkennbar, wenn sie als Ziel gewählt werden können; drei aufgeschobene Kleinigkeiten (deutsche Mana-Farben, WebSocket-Port aus der URL, Log-Filter).

**Architecture:** `WebGuiGame` hängt sich beim `setGameView` als `Observer` an `GameView.getGameLog()` (dasselbe Muster wie `AiMatch`) und schickt jede neue Zeile als `log`-Nachricht mit Kategorie; die letzten 200 Zeilen werden gepuffert und beim Reconnect erneut gesendet. "Spieler wählbar" wird aus dem aktiven Forge-Input abgeleitet (`InputSelectTargets` auf der `InputQueue` des menschlichen Controllers) und als `PlayerSnap.targetable` gesendet. Frontend: Log-Panel mit Kategorie-Farben und Filter (Mana/Phase standardmäßig aus), Spieler-Header mit gestricheltem Ziel-Rahmen, `ws.ts` liest `?ws=` / `?wsPort=`.

**Tech Stack:** wie M4.

## Global Constraints

- Forge-Submodule bleibt unverändert; Protokoll abwärtskompatibel (neue Felder optional).
- `log`-Nachricht: `{type:"log", text, kind?, card?}` – `kind` = Name der `GameLogEntryType`-Konstante (`TURN`, `ZONE_CHANGE`, `DAMAGE`, `LIFE`, `LAND`, `DISCARD`, `COMBAT`, `INFORMATION`, `STACK_RESOLVE`, `STACK_ADD`, `EFFECT_REPLACED`, `MANA`, `PHASE`, `MULLIGAN`, `GAME_OUTCOME`, `MATCH_RESULTS`, `PLAYER_CONTROL`, `ANTE`, `DRAFT`); Bridge-eigene Zeilen (`message`, Fehler) haben kein `kind` bzw. bleiben `error`.
- Reconnect: nach `lobby` und `state` werden die gepufferten Log-Zeilen (max. 200, älteste zuerst) gesendet, dann die offenen `choice`s.
- `PlayerSnap.targetable` (Boolean, optional) = `true`, wenn der aktuelle Input des menschlichen Controllers ein `InputSelectTargets` ist. Nur für den menschlichen Sitz (Zuschauer: nie).
- Threading wie bisher; der Log-Observer wird auf dem Game-Thread aufgerufen und darf nur `out.send` (thread-sicher) und den Puffer (synchronisiert) anfassen.
- Commit-Messages: deutsch, Kleinschreibung, Präfix `m5:`, Trailer `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>` (verbatim, unabhängig vom Modell).
- Maven aus `bridge/` (Timeout 600000 ms, nie zwei Prozesse, Nutzer-Bridge auf 8080/8081 in Ruhe lassen); Frontend: `npm test`, `npm run build`, `npm run layout-check` (Fixtures table, table-1v1, spectator, table-cmd-cast) müssen grün bleiben; Screenshots wie gehabt.


Methoden:

```java
    private void remember(Messages.LogLine line) {
        synchronized (recentLog) {
            recentLog.addLast(line);
            while (recentLog.size() > LOG_MAX) recentLog.removeFirst();
        }
    }

    /** Kopie der letzten Log-Zeilen (älteste zuerst) – für den Reconnect. */
    public List<Messages.LogLine> recentLog() {
        synchronized (recentLog) {
            return new ArrayList<>(recentLog);
        }
    }

    private void sendLog(Messages.LogLine line) {
        remember(line);
        out.send(line);
    }

    @SuppressWarnings("deprecation")
    private void watchLogOf(GameView gv) {
        if (observedLog != null && logObserver != null) {
            observedLog.deleteObserver(logObserver);
        }
        observedLog = null;
        logObserver = null;
        logSeen = 0;
        if (gv == null || gv.getGameLog() == null) return;
        forge.game.GameLog log = gv.getGameLog();
        logObserver = (o, arg) -> {
            List<forge.game.GameLogEntry> all = log.getAllEntries();
            for (; logSeen < all.size(); logSeen++) {
                forge.game.GameLogEntry e = all.get(logSeen);
                sendLog(new Messages.LogLine(e.message(), e.type().name(),
                        e.sourceCard() == null ? null : e.sourceCard().getId()));
            }
        };
        observedLog = log;
        log.addObserver(logObserver);
    }
```

`setGameView` ersetzen:

```java
    @Override
    public void setGameView(GameView gameView0) {
        super.setGameView(gameView0);
        if (gameView0 != null && gameView0 != observedGameViewForLog()) {
            synchronized (recentLog) { recentLog.clear(); }
            watchLogOf(gameView0);
        }
        push();
    }

    private GameView observedGameViewForLog() {
        return observedLog == null ? null : getGameView();
    }
```
