Base: tag `forge-2.0.15` (commit 4ec5f1a2). Maven version `2.0.15-mtgplayer`.

Since 2026-10-06 the fork sits on `forge-2.0.15` (branch `mtg-player-2.0.15`, see "Switch to 2.0.15" below).
The commit hashes in the table are those of the **old** state on `forge-2.0.14` (head of the table: `903f0f1d`);
when the branch was recreated the code commits got new hashes, but their content and reasoning still apply.
The tag `mtg-player-2.0.14` sits on `840f3cc0` (merge of the first card data sync, pull request #1 in the fork,
2026-10-06) and has `903f0f1d` as an ancestor; the shipped packages point at `903f0f1d`, so the tag covers them
as well.
The card data commit `0e30eaac` and the version commit `952c5e1a` were not carried over (2.0.15 brings most of
the cards itself — 54 cards that upstream only added after the tag are missing, see "Switch to 2.0.15" below;
the version is set anew in the POMs).

## Switch to 2.0.15 (2026-10-06): what it brings in cards

Measured with `--kartendaten-pruefen` (builds every card via `CardFactory.getCard` in a game context).
"Buildable" means: the card comes into being without an exception; the returning cards were not played with.

**Method.** The same card data through both engines: Forge's `upstream/master` (commit `0d425a66`, 2026-10-06
18:45 UTC) laid over `cardsfolder`, `editions` and `tokenscripts`, once under `2.0.14-mtgplayer` and once under
`2.0.15-mtgplayer`. Cross-check of the measurement: under 2.0.14 exactly **88** cards fail — the 78 of the
exclusion list of 2026-10-06 (identical set of names) plus the ten "kept on our previous version". The difference
between `upstream/master` and the sync result (`d72bad69`) is exactly those 78 files and 14 changed scripts (the
ten plus four further pure data changes, all buildable in both engines).

**Card count (`getUniqueCards`), same data, both engines:** 33469 / 33469 (state before the sync),
33523 / 33523 (sync of 2026-10-06), 33600 / 33600 (`upstream/master` raw). The new engine knows no fewer cards.

**The 78 excluded cards: 38 come back, 40 do not.**

| Cause (cards) | Under 2.0.15 |
|---|---|
| `Empower` (34) | all 34 buildable |
| `FlippedCoinOnce` (1), `CantBeBeamedUp` (1) | buildable |
| `CombatDamageNegatePower` (1, Loot, the Anomaly), `IgnorePlaneswalkerZeroLoyaltyRule` (1, Sanctum Lurker) | buildable |
| `PutSticker` (35) and `StickerPlaced` (5) — the sticker mechanic | **stay excluded**: 2.0.15 knows neither the `ApiType` `PutSticker` nor the `TriggerType` `StickerPlaced` (not to be found in any class of the four Forge modules) |

**The ten cards that stayed on the old version during the sync: 8 come back on upstream's version, 2 do not.**
2.0.15 knows `CanBlockIfShadow` (Aether Web, Aetherflame Wall, Heartwood Dryad, Wall of Diffusion),
`ManaRestriction` (Hogaak, Arisen Necropolis; Imperiosaur; Myr Superion) and `CantGainControl` (Guardian Beast).
It does not know `DrawFromBottom` (Lantern of Undersight, River Song) — both stay on the old version.

**Expected result of the next sync on 2.0.15:** 40 cards on the exclusion list (all stickers), two on the old
version (`DrawFromBottom`), card count 33560 by calculation instead of 33523 (33600 minus the 40 sticker cards).

**Card count when merely moving the pointer (without a new sync).** The branch `mtg-player-2.0.15` carries the card
data of the tag `forge-2.0.15`, not that of the syncs: 33469 (the pointer up to here, `903f0f1d`) → 33507 (+38),
but **16 fewer** than the meanwhile merged `mtg-player` (`840f3cc0`, sync of 2026-10-06, 33523): +39 names that
2.0.15 brings itself (34 Empower cards, Loot, Marooned, Sanctum Lurker, Chira, Command the Stage among others), −1
(Cybernetics Specialist, removed upstream) and −54 cards that upstream only added after 2.0.15. The first sync on
the new base brings them back. The exclusion list is emptied; it applies per engine version.

**Decision: the engine switch and the data switch stay separate (16 cards fewer is intended, not a loss).**
The branch `mtg-player-2.0.15` carries the card data of the tag `forge-2.0.15`: `getUniqueCards` returns 33507
there, against 33523 on the previous fork branch `mtg-player` (the sync of 2026-10-06 already merged) — so 16
fewer. That is known and decided this way: switching the engine should not be mixed up with switching the card
data, so that faults can be attributed unambiguously to one of the two causes. Right after the switch the card
sync is started once by hand; it makes up the difference. Anyone missing a card during that gap finds it again
after the sync.
